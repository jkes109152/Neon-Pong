# 技術計畫：NEON ARENA｜Cyber Pong

## 技術選擇

- 使用原生 HTML、CSS、JavaScript 與 Canvas 2D，保持可直接開啟與 GitHub Pages 相容。
- 使用 `window.requestAnimationFrame` 驅動單一遊戲迴圈，更新時以 timestamp 算出 `dt`。
- 使用 CSS 建立控制面板、比分板、響應式排版與霓虹視覺；Canvas 專注於球桌、球拍、球與粒子。
- 使用 Web Audio API 產生短促合成音，不提交音檔與第三方資產。
- 使用 `localStorage` 儲存最佳連擊、最快球速與靜音偏好。

## 模組與責任

| 模組 | 責任 |
| --- | --- |
| `index.html` | 語意化介面、Canvas、HUD、操作按鈕 |
| `styles.css` | 電競舞台視覺、狀態樣式、手機響應式排版 |
| `game.js` | 遊戲狀態、輸入、AI、物理、渲染、音效與紀錄 |
| `tests/smoke-test.js` | 不啟動瀏覽器的結構與關鍵功能靜態檢查 |
| `.github/workflows/validate.yml` | GitHub-hosted Node.js 靜態驗證 |

## 遊戲迴圈

1. 讀取鍵盤／指標輸入，更新玩家球拍目標位置。
2. 在球朝 CPU 方向時，以邊界反射模型預測落點，依難度加入反應延遲與誤差。
3. 以 `dt` 更新球、球拍、粒子；檢查邊界、球拍碰撞與得分。
4. 更新比分、紀錄與狀態訊息。
5. 重繪背景網格、球桌線、粒子、球拍與帶拖影的球。

## 可靠性與邊界

- 每幀 `dt` 上限為 33ms，避免分頁切回或低幀率造成球穿透球拍。
- 球拍目標位置限制在球桌內邊界；CPU 的預測落點亦會被限制。
- 得分後先進入 point 狀態，避免同一幀重複得分。
- 音效建立失敗或瀏覽器不支援時不阻塞遊戲。
- 紀錄讀取使用數字轉換並以 0 作為缺省值。

## 驗證策略

- Node 語法檢查：`node --check game.js`。
- 靜態煙霧測試：檢查 Canvas、動畫迴圈、AI、碰撞、輸入、難度與響應式樣式。
- 手動快速驗收：啟動、三種難度、兩種輸入、暫停、得分、7 分結束、重新整理後紀錄保留。
